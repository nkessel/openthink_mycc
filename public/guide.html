Start a Climate Organization Map for your region

The MA Climate Organization Map is free to copy. This guide walks you through running one for another state or region: your own map, your own Google Sheet and forms, your own point people.

Steps (about an hour, plus waiting for DNS)
  1. What you will have
  2. Copy the code on GitHub
  3. Clear out Massachusetts and name your region
  4. Set up the Google Sheet and forms
  5. Connect the site to your sheet
  6. Test it
  7. Get a climateorgmap.earth address
  8. Get updates from the MA map
  9. Who owns what (plan a handover)

1. What you will have

Three pieces, all free:

PieceWhat it doesWhere it lives
The websiteThe map people look at. It never changes data itself.A copy (fork) of the code on GitHub, published with GitHub Pages
The Google SheetThe source of truth: every coalition, group, event, project and action, and who may edit each one.Your Google Drive (only your core team can open it)
Google FormsHow point people add and fix their group's information. They sign in with Google; changes from people not on the Editors tab wait for your review.Made for you by the sheet's script

The sheet's script also publishes a public data link (an Apps Script "web app") that the website reads. It only ever shares public information, never the Editors, Needs Review, Feedback or Change Log tabs.

You need: a GitHub account, a Google account for the sheet (ideally a shared team account, see step 9), and a computer with Node.js 22 or newer, or GitHub Codespaces (runs in the browser, nothing to install).

2. Copy the code on GitHub

  1. Open github.com/nkessel/openthink_mycc and click Fork. Uncheck "Copy the main branch only": the site is published from development_branch.
  2. In your fork: Actions tab → I understand my workflows, go ahead and enable them.
  3. Settings → Pages → Build and deployment → Source: GitHub Actions.
  4. Settings → Environments → github-pages → Deployment branches: add development_branch (by default only main may publish).

3. Clear out Massachusetts and name your region

Open your fork on your computer (git clone, then npm install) or in a Codespace (Code → Codespaces → Create). Make a branch, then run:

node scripts/start-new-region.mjs        # shows what it will change
node scripts/start-new-region.mjs --yes  # makes the changes

It empties the map data, deletes the Massachusetts logos, research and extra maps, clears the Massachusetts form links, and turns off the Vermont/Oregon/USA maps. The code, the topic lists and the geography files stay.

Then edit these by hand:

FileWhat to change
src/region.config.tsYour map's name and short name, state name and code, time zone, where the geographic map opens (bounds), and your main city (fallback: where a group with no address yet is placed). Set geo: [] unless you add town outlines for your state (see src/geodata.ts).
apps-script/Code.gsREGION at the top (the same name and state, a box around your state for checking pins, your main city's point, and example towns and groups for the form hints), and SEED_URL = '' so your sheet starts empty.
index.htmlThe page title and the land acknowledgement: write your own, for the land your team is on.
README.mdYour map's name and who to contact.

Run npm run build to check nothing broke, then open a pull request into development_branch on your fork and merge it.

4. Set up the Google Sheet and forms

  1. Make a new, blank Google Sheet, named after your map (for example "WI Climate Organization Map data").
  2. Extensions → Apps Script. Delete what is in Code.gs and paste in your edited apps-script/Code.gs. Click Save.
  3. Still in Apps Script: Project settings (gear icon) → Script properties → Add script property. Name: ADMIN_EMAILS. Value: your core team's emails, separated by commas. These people can edit everything, approve changes and get alerts. (They are kept here, not in the code, so your public copy holds no personal emails.)
  4. Close Apps Script and reload the sheet. A menu with your map's name appears. Choose Set up sheet + forms (run once) and allow the permissions Google asks for. It makes the tabs, builds the five forms, shares them with your admins, and puts their links on the Start Here tab.
  5. Back in Apps Script: Deploy → New deployment → type: Web app. Execute as: Me. Who has access: Anyone. Click Deploy and copy the web app URL.
Later changes to the script: the web app keeps serving the version it was deployed with. After pasting a new Code.gs, go to Deploy → Manage deployments → ✏️ → Version: New version → Deploy. The URL stays the same.

5. Connect the site to your sheet

In one more pull request into development_branch:

  1. Paste the web app URL into LIVE_DATA_URL in src/data.config.ts.
  2. From the sheet's Start Here tab, copy the row "For the site: paste into src/forms.config.ts" and paste it over FORMS in src/forms.config.ts.
  3. Run node scripts/form-fields.mjs. It reads your forms and writes src/forms.fields.json, so the site's Edit buttons open the forms with everything filled in.

Then, on GitHub: Settings → Secrets and variables → Actions → Variables → New repository variable: OPENTHINK_DATA_URL = the same web app URL. This turns on the nightly backup: a pull request with the latest data, only when something changed.

6. Test it

  1. Open Actions → Deploy to GitHub Pages and wait for the green check. Your map is at https://<your-github-name>.github.io/<repo-name>/.
  2. Add version.json to that address to see which version is live.
  3. Press + on the map and add a test group through the form. As an admin, your change is applied straight away; reload the map and it appears (within about a minute).
  4. Try it as someone else: a change from an email not on the Editors tab should land in Needs Review, and your admins should get an email.
  5. When you are happy, delete the test rows from the sheet's tabs (Organizations, Events and so on).
Adding your first groups: type them straight into the Organizations and Coalitions tabs (the column names are explained on Start Here), or send each group the "Update your organization" form. On the Editors tab, add each group's point person (up to three) with the group's id.

7. Get a climateorgmap.earth address

Maps can have their own address, like ma.climateorgmap.earth.

  1. Ask first. Send the request through the MA map's feedback form with the address you'd like, your map's GitHub link and who maintains it. The climateorgmap.earth team approves requests.
  2. Once approved, set the domain in your repo first: Settings → Pages → Custom domain: <region>.climateorgmap.earth. Doing this before the DNS record exists is GitHub's advice against someone else claiming the address.
  3. The climateorgmap.earth team then adds a DNS record: CNAME <region> → <your-github-name>.github.io.
  4. When the address works, tick Enforce HTTPS in the same Pages settings (it can take up to a day to become available).

If a map is shut down, its DNS record is removed so the address can't be taken over.

8. Get updates from the MA map

  1. On your fork's page: Sync fork → Update branch (for development_branch). Your own settings files may show conflicts: keep your values.
  2. If apps-script/Code.gs changed: paste it into Apps Script again (keep your REGION block and SEED_URL), save, and deploy a new version (step 4's note).
  3. In the sheet, run Update the forms from your map's menu. It is safe to run any time.

9. Who owns what (plan a handover)

  • The sheet's script and its web app run as the Google account that set them up. If that person leaves and their account is closed, the forms stop recording and the map stops updating. Use a shared team Google account if you can, or write down who will take over.
  • The GitHub fork belongs to whoever made it. Add a second maintainer (Settings → Collaborators).
  • Keep the sheet shared only with your core team. Point people never need to open it: they use the forms.
